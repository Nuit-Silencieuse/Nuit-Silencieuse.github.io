SSH 从原理到 Windows 远程开发实践

这篇文档整理 SSH 的核心概念、常用配置、Windows 上的使用方法，以及一套适合云服务器开发和 Codex CLI 的工作流。目标是以后忘了某个命令或配置项时，可以快速回来看。

阅读路线：

  • 先理解 SSH 在解决什么问题，以及密钥登录为什么安全。
  • 再完成 Windows 本机和云服务器之间的基础连接。
  • 然后用 SSH config、PowerShell profile、tmux 把连接体验优化到适合日常开发。
  • 最后掌握常用命令、安全建议、排错方法和可复用模板。

一、建立心智模型

这一部分关注 SSH 的基本原理。先把“客户端、服务器、密钥、指纹、认证”这些概念弄清楚，后面的配置就会更容易理解。

1. SSH 是什么

SSH，全称 Secure Shell，是一种安全远程登录协议。我们平时说的“连服务器”，大多数时候指的是用 SSH 从本地电脑登录到远程 Linux 服务器。

典型用途：

  • 远程登录云服务器
  • 执行 Linux 命令
  • 上传和下载文件
  • 远程开发
  • Git 免密访问
  • 端口转发
  • 让 Codex、tmux、服务进程在云服务器上长期运行

含义是：使用本机的 SSH 客户端，连接 111.222.111.222 这台服务器，并以 root 用户登录。

2. SSH 的基本工作原理

SSH 连接大致分为几步：

  1. 客户端连接服务器的 SSH 端口，默认是 22。
  2. 客户端和服务器协商加密算法。
  3. 服务器向客户端证明“我是这台服务器”。
  4. 客户端向服务器证明“我是被允许登录的用户”。
  5. 验证通过后，双方建立加密通道。

这个过程里有两个容易混淆的概念：

  • 服务器身份验证：防止你连到假的服务器。
  • 用户身份验证：服务器确认你有没有权限登录。

第一次连接服务器时，你可能会看到：

这是 SSH 客户端在告诉你：它以前没见过这台服务器，不知道它是不是可信。输入 yes 后，服务器指纹会被记录到本机的：

以后如果这台服务器的指纹突然变化，SSH 会警告你。这可能是服务器重装了，也可能是中间人攻击，需要谨慎确认。

3. 密码登录和密钥登录

SSH 常见登录方式有两种：

  • 密码登录：输入服务器用户密码。
  • 密钥登录：本地保存私钥，服务器保存对应公钥。

推荐使用密钥登录。它更适合自动化、远程开发、Git、Codex 等长期使用场景。

密钥登录涉及一对文件：

私钥只放在你自己的电脑上，不能泄露。公钥可以放到服务器上。

服务器通常把允许登录的公钥放在：

当你登录时，流程大致是：

  1. 客户端告诉服务器：我要用某把公钥对应的私钥登录。
  2. 服务器检查 authorized_keys 里是否有这个公钥。
  3. 服务器发一个挑战给客户端。
  4. 客户端用私钥完成签名。
  5. 服务器用公钥验证签名。
  6. 验证通过，允许登录。

关键点：登录过程中私钥不会被传给服务器。

六、安全与排错

SSH 配置完成后，最重要的是知道哪些文件不能泄露，以及连接失败时应该按什么顺序定位问题。

1. 安全建议

不要把私钥发给别人：

可以公开或粘贴到服务器的是公钥：

建议：

  • 云服务器尽量只开放必要端口。
  • 如果不需要密码登录，可以在确认密钥登录正常后关闭密码登录。
  • 不要把私钥提交到 Git 仓库。
  • 生产服务器不要随意使用 root，长期建议创建普通用户并配置 sudo。
  • 给重要私钥设置 passphrase 可以提高安全性，但会降低免交互便利性。

3. 核心记忆点

  • SSH 是加密远程登录协议。
  • 私钥留在本机，公钥放到服务器。
  • authorized_keys 决定哪些公钥能登录某个用户。
  • known_hosts 记录服务器身份指纹。
  • ~/.ssh/config 用来给复杂连接起别名。
  • IdentityFile 指定私钥。
  • IdentitiesOnly yes 避免错误密钥干扰。
  • ServerAliveInterval 可以减少空闲断线。
  • RemoteCommand 可以让登录后自动执行命令。
  • RequestTTY yes 适合远程运行 tmux、vim、codex 等交互程序。
  • tmux 可以让 Codex 会话不怕 SSH 断线。
  • VS Code Remote SSH 应连接普通 Host，不要连接带 RemoteCommand 的 Host。
