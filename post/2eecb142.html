Termius 全平台 SSH 管理与远程开发实践

这篇文档整理 Termius 的定位、核心概念、配置方式、安全取舍，以及它和 Windows SSH config、云服务器、tmux、Codex CLI 的配合方式。目标是把 Termius 当成一个可以长期复用的跨设备 SSH 工作台，而不是只把它当成“能连服务器的软件”。

阅读路线：

  • 先理解 Termius 解决的问题，以及它和原生 SSH 的关系。
  • 再掌握 Hosts、Keychain、Vault、Snippets、Port Forwarding 等核心对象。
  • 然后把已有云服务器 aliyun 配置迁移到 Termius。
  • 最后建立一套适合手机、平板、Windows 和 Codex 的使用习惯。

一、建立心智模型

Termius 的重点不是替代 SSH 协议，而是把 SSH 连接信息、密钥、常用命令和跨设备同步集中管理起来。

1. Termius 是什么

Termius 是一个现代 SSH 客户端，支持 Windows、macOS、Linux、iOS、Android 等平台。它可以保存服务器连接信息、SSH 密钥、端口转发规则、命令片段和已知主机记录，并通过加密 Vault 在多设备之间同步。

从使用者视角看，Termius 主要解决这些问题：

  • 多台设备上重复配置服务器很麻烦。
  • 手机或平板上临时登录服务器不方便。
  • IP、用户名、端口、密钥散落在不同地方。
  • 常用命令经常要从笔记里复制。
  • 团队共享服务器连接信息容易混乱。
  • 远程开发时需要快速进入固定目录和会话。

2. Termius 适合什么场景

Termius 特别适合这些场景：

  • 在 Windows 电脑、笔记本、手机、平板之间共享 SSH 主机列表。
  • 临时在手机上登录服务器检查日志、重启服务、处理紧急问题。
  • 给常用命令做 Snippets，减少重复输入。
  • 管理多个云服务器、开发机、测试机、生产机。
  • 使用 SFTP 浏览服务器文件。
  • 为 Web 服务配置本地端口转发。
  • 团队共享 Hosts、Keys、Snippets、Port Forwarding 规则。

但它不一定适合所有情况：

  • 如果只在一台电脑上开发，原生 ~/.ssh/config 已经很轻量。
  • 如果对私钥绝对不能进入第三方同步服务，应该谨慎使用 Vault 同步密钥。
  • 如果需要高度自动化脚本，命令行 OpenSSH 更直接。
  • 如果你在 VS Code Remote SSH 中开发，仍建议保留原生 SSH config。

二、核心对象

理解 Termius 的关键，是理解它把 SSH 连接拆成了几个对象：Host、Key、Credential、Vault、Snippet、Port Forwarding。

2. Keychain：集中管理密钥和凭据

Keychain 是 Termius 中管理 SSH keys、密码、证书等凭据的地方。

常见操作：

  • 生成新的 SSH key。
  • 导入已有私钥。
  • 给某个 Host 绑定指定 key。
  • 为 key 设置 passphrase。
  • 复制公钥到服务器。

Termius 官方文档说明，它可以生成 ED25519、ECDSA、RSA 等现代 SSH key 类型，并把生成的密钥保存在 Vault 中。

对个人开发者来说，最重要的问题是：要不要把本机已有私钥导入 Termius。

有两种策略：

优点：

  • 服务器端不用再加新公钥。
  • 所有设备使用同一把 key，配置简单。

缺点：

  • 这把私钥会进入 Termius 的 Keychain/Vault 管理体系。
  • 如果你对第三方加密同步不放心，这不是最保守的方案。

优点：

  • 和 Windows 本机 id_ed25519 分开。
  • 可以单独撤销 Termius 使用的公钥。
  • 更容易区分“命令行使用的 key”和“Termius 使用的 key”。

缺点：

  • 需要把新的公钥追加到服务器 authorized_keys。

我更推荐策略 B。尤其是生产服务器，建议每个主要入口都有独立 key，方便以后撤销。

3. Vault：跨设备同步和共享的容器

Vault 是 Termius 用来保存和同步数据的加密容器。它可以包含：

  • Hosts
  • Groups
  • Keys
  • Snippets
  • Port Forwarding rules
  • Known Hosts

Termius 官方文档把 Vault 描述为跨团队和跨设备共享访问结构的核心。Personal Vault 通常用于个人私有数据；团队 Vault 用于团队共享。

4. 从 SSH config 导入

导入后的检查重点：

  • HostName 是否正确变成 Address。
  • User 是否正确。
  • Port 是否正确。
  • IdentityFile 是否正确关联到 Keychain。
  • 带 RemoteCommand 的 Host 是否需要改成 Snippet。
  • known_hosts 是否需要导入或重新确认。

不要假设导入后就完全等价。Termius 的 Host 模型和 OpenSSH config 不是一一对应的，尤其是复杂配置，例如：

  • RemoteCommand
  • ProxyJump
  • ProxyCommand
  • LocalForward
  • 多 IdentityFile
  • Include

导入后最好手动测试。

3. 移动端操作原则

移动端适合应急，不适合做高风险变更。

建议：

  • 多用查看命令，少做破坏性操作。
  • 避免在手机上手敲长命令。
  • 对 rm、mv、chmod -R、chown -R、git reset 等命令格外谨慎。
  • 生产服务器上执行重启、部署、删除前先确认当前目录。
  • 长任务放进 tmux，不要直接跑在普通 SSH 会话里。

五、安全策略

Termius 的便利来自同步，但同步也意味着需要认真考虑私钥和账号安全。

1. Vault 的安全边界

Termius 官方说明其 Vault 使用端到端加密，关键数据在客户端由密码派生的 key 保护，并在传输和静态存储时受到保护。官方安全文档也说明了账号认证、Personal Vault 和 Shared Vault 的加密机制。

这意味着你应该重点保护：

  • Termius 账号密码
  • Master password
  • 2FA
  • 已登录设备
  • Vault 权限
  • 导入 Termius 的私钥

2. 私钥管理建议

按照安全强度从高到低，可以分成三种模式：

最保守。服务器 authorized_keys 中会有多条公钥。哪台设备丢失，就撤销哪条公钥。

适合：

  • 生产服务器
  • 高权限 root 登录
  • 对第三方同步非常谨慎的场景

便利性和安全性折中。Windows 命令行 SSH 使用 id_ed25519，Termius 使用另一把 key。

适合：

  • 个人云服务器
  • 多设备应急维护
  • 希望能快速撤销 Termius 入口

最方便，但边界最不清晰。所有入口共用同一把 key。

适合：

  • 低风险服务器
  • 临时过渡
  • 明确接受 Termius Vault 同步私钥的风险

我建议优先使用模式 B。

3. 账号安全设置

建议开启：

  • 强密码
  • 2FA
  • 设备管理
  • Master password 保护
  • 生物识别解锁，仅作为本机便利入口

官方账号管理文档说明，Termius 支持通过 TOTP 或 Authy 启用 2FA；如果忘记密码或丢失 2FA，重置密码会影响已有数据访问。因此恢复码和账号恢复策略要提前想好。

八、排错清单

1. Termius 连不上，但 Windows ssh 能连

重点检查：

  • Address 是否写成了真实 IP，而不是 SSH config 别名。
  • Username 是否一致。
  • Port 是否一致。
  • Key 是否选对。
  • 私钥是否需要 passphrase。
  • 公钥是否在服务器对应用户的 authorized_keys 中。
  • 服务器安全组是否允许当前网络访问 22 端口。

常见原因：

  • key 不匹配。
  • 公钥没有添加到服务器。
  • 添加到了错误用户。
  • 服务器禁用了 root 登录。
  • 文件权限不对。

3. Host key 警告

如果服务器重装过系统，host key 可能变化。Termius 和 OpenSSH 一样，会基于 Known Hosts 判断服务器身份。

遇到警告时先确认：

  • 服务器是否重装。
  • IP 是否换到了另一台机器。
  • 云厂商控制台里的实例是否正确。
  • 是否存在中间人风险。

确认无误后再更新 known host。

4. 同步后手机上看不到 Host

检查：

  • 是否登录同一个 Termius 账号。
  • Host 是否放在 Personal Vault 或你有权限的 Vault。
  • 当前设备是否完成同步。
  • 网络是否正常。
  • 是否启用了正确的工作区或 Vault。

十一、核心记忆点

  • Termius 是 SSH 客户端和连接管理器，不是新的远程登录协议。
  • Host 对应一台远程机器的连接配置。
  • Keychain 管理 SSH keys、密码和凭据。
  • Vault 用来加密保存和跨设备同步 Termius 数据。
  • Snippets 适合保存高频命令，尤其适合移动端。
  • Port Forwarding 适合远程调试 Web、数据库和内部服务。
  • 不要无脑把最高权限私钥导入同步工具。
  • 更推荐 Termius 使用单独 SSH key。
  • 手机适合应急维护，不适合做高风险变更。
  • Codex 应该跑在服务器 tmux 中，再通过 Termius 恢复会话。
  • VS Code Remote SSH 仍建议使用普通 SSH config Host。
  • Windows Terminal、Termius、VS Code 可以并存，分别承担不同角色。
